**2026-07-25 — THE root cause of Dagger's endless turn/heading troubles (supersedes many earlier turn theories in [[dagger-outdoor-ugv-project]]).**

The Cube is configured **compassless**: `COMPASS_ENABLE=0` (a mag IS present, `COMPASS_DEV_ID=97539`, but disabled — almost certainly due to magnetic interference from the 350kg tracked rover's motors/steel), and **`EK3_SRC1_YAW=8` = GSF** (EKF-GSF yaw estimator), no fallback (SRC2/3_YAW=0). AHRS_EKF_TYPE=3 (EK3), all 3 IMUs used (EK3_IMU_MASK=7), static gyro offsets all ~0 (INS_GYROFFS_Z ok — NOT a gyro-cal problem).

**Consequence:** GSF derives yaw from **GPS translational velocity**, so yaw is only observable **while the vehicle is moving/translating**. At rest and **during in-place rotation** (no translational velocity) EK3's yaw + gyro-bias states drift. Observed symptoms this session:
- `/mavros/imu/data` gz = **0.11 rad/s (6.2 deg/s) steady bias at rest** (this is ArduPilot's EK3/AHRS-fused rate, from the ATTITUDE msg — what ArduPilot's OWN control loop uses), while `/mavros/imu/data_raw` (raw sensor gyro) = **0.0** (clean). So the bias is EK3's yaw/bias estimate, NOT the sensor.
- **GUIDED self-rotates at rest with ZERO command**: ArduPilot's steering-rate loop sees the phantom +0.11 rate, steers to null it → rover physically rotates → bias persists → runaway (~128 deg before caught). NOT our software (teleop/mux/setpoint all 0 in chain_monitor).
- This ALSO explains years of "turn hunting": yaw feedback degrades exactly when the rover pivots in place. **A heavy tracked rover doing 180 deg in-place turn-arounds is the worst case for compassless GSF.**

**Our OWN localization was decoupled from this** (2026-07-25): `ekf_local.yaml` `imu0` switched `/mavros/imu/data` -> **`/mavros/imu/data_raw`** (fuse vyaw only; raw gyro clean) → our /odometry/filtered rest-drift went 6.2 -> 0.0 deg/s. But this does NOT fix ArduPilot's INTERNAL control, which still uses the biased EK3 rate → GUIDED still self-rotates.

**ARCHITECTURAL FORK (user to decide):**
- (A) **Re-enable + calibrate the compass** (`COMPASS_ENABLE=1`, `EK3_SRC1_YAW=3` GPS+compass fallback). Gives yaw at rest AND during rotation → in-place turns become possible. RISK: reintroduces the interference that got it disabled; needs careful cal + interference check (external mag in GPS mast, away from motors, may be OK).
- (B) **Stay compassless (GSF), design nav for motion-only yaw**: never in-place pivot; use ARCING turns (forward+steer) so GPS velocity keeps yaw observable; start each mission driving straight to converge GSF. Waypoint following with wide turns works; sharp turn-arounds don't.
